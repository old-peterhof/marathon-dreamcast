# Session of 2026-09-02 — font VRAM, and a GLdc mipmap bug

Branch: `gl-forward`, on top of `2592e4d`. Everything below **builds** (`./build.sh
GL=1`, exit 0, clean link). **Nothing below has been run** — no Flycast, no
hardware. Treat every number as measured-from-source arithmetic unless it says

This session began as "why are font atlases in VRAM when nothing is using them",

## 1. What the fonts actually cost, and where the number comes from

`data/Fonts` is a classic Mac resource fork (`FOND` family records, `NFNT`
bitmap strikes). It can be parsed offline, so every atlas dimension is derivable
without running anything: `FontSpecifier::OGL_Reset` sizes each atlas from the
font's own per-glyph widths.

Parsing it gives two `FOND`s — Monaco is resource id 4, Courier is 22, which is
what the `"#4"` / `"#22"` fields in the `FontSpecifier` declarations mean — and
six `NFNT` strikes:

| font | pt | chars | ascent | descent |
|---|---|---|---|---|
| Monaco | 5 | 0..255 | 5 | 1 |
| Monaco | 9 | 0..217 | 9 | 2 |
| Monaco | 12 | 0..217 | 12 | 3 |
| Monaco | 18 | 0..255 | 18 | 4 |
| Courier | 12 | 0..255 | 10 | 2 |
| Courier | 14 | 0..255 | 11 | 3 |

Replaying `OGL_Reset`'s arithmetic over those width tables gives what
`OGL_StartRun()` uploads, at 2 bytes per texel (GLdc stores 16-bit regardless of
the source format — `OGL_Textures.cpp:1233` records this):

| where | font | atlas | KB |
|---|---|---|---|
| `GetOnScreenFont()` | Monaco 12 plain | 256x256 | 128 |
| `OGL_ResetMapFonts` | Monaco 5 bold | 128x128 | 32 |
| `OGL_ResetMapFonts` | Monaco 9 bold | 256x128 | 64 |
| `OGL_ResetMapFonts` | Monaco 12 bold | 256x256 | 128 |
| `OGL_ResetMapFonts` | Monaco 18 bold | **512x256** | 256 |
| `OGL_ResetMapFonts` | Monaco 18 plain (map title) | **512x256** | 256 |
| `OGL_ResetHUDFonts` | Monaco 9 bold | 256x128 | 64 |
| `OGL_ResetHUDFonts` | Monaco 9 bold | 256x128 | 64 |
| `OGL_ResetHUDFonts` | Monaco 9 bold | 256x128 | 64 |
| `OGL_ResetHUDFonts` | Monaco 9 plain | 256x128 | 64 |
| | | **10 atlases** | **1120** |

That is exactly the "10 textures, 1120 KB" the overnight run measured on
hardware, reproduced from the data files. The offline model and the hardware
measurement agree, so the model can be trusted for the rest of this.

Three things fall out of the table:

- **736 KB of it is the overhead map**, including both 512x256 atlases. It was
  resident from level load whether or not the map was ever opened.
- **The two 512x256 atlases are Monaco 18** — map annotations at the largest
  scale, and the map title.
- **192 KB is duplicate.** `InterfaceFonts[]` declares `{"Monaco", 9, styleBold,
  "#4"}` three times, and `load_font` already shares the `sdl_font_info` behind
  (font id, size), so those three atlases are byte-identical. A fourth identical
  one is built for the map's smallest annotation. Not yet fixed.

The terminals are **not** in this list. `_computer_interface_font` is Courier 12
and `OGL_ResetHUDFonts` does not touch it, which is consistent with terminals
going through the surface path on this branch. Courier is never uploaded as an
atlas at all.

## 2. The wrong turn: switching the overhead map to software

**Tried, wrong, reverted. Do not retry without reading this.**

The reasoning was: `OverheadMap_SDL_Class::draw_text` uses only `FontData.Info`
and `FontData.Style` and calls the software glyph blitter into `world_pixels`, so
a software map needs no atlas at all — 736 KB of VRAM and the heap behind it stop
existing. The renderer is chosen by one flag at `overhead_map.cpp:326`
(`OGL_MapActive`), which comes from `OGL_Flag_Map` in the OpenGL preferences. So:
drop `OGL_Flag_Map` from the DC defaults in `OGL_Setup.cpp`.

It looked safe because `screen_sdl.cpp:943` reads

```c
if (world_view->terminal_mode_active || (world_view->overhead_map_active && !OGL_MapActive)) {
    update_screen(BufferRect, ViewRect, HighResolution);
}
```

— a branch that already names the software-map case.

**That branch does not present anything under GL.** `update_screen` blits
`world_pixels` into `main_surface`, and under GL `main_surface` is an
`SDL_OPENGL` surface with nothing to blit into. The proof is in this tree: the
terminal fix at `screen_sdl.cpp:1151` exists precisely because of this, and says
so —

> Terminals draw into world_pixels, the software world buffer. Under GL that
> buffer is still allocated and still written, but nothing ever puts it on
> screen [...] **That is why terminals were blank.**

Terminals needed an explicit `dc_ui_draw_surface(world_pixels, ...)` call to
appear. A software overhead map would need the same, and would then trade 736 KB
of atlases for a ~600 KB surface re-uploaded every frame the map is open.

Reverted; `OGL_Flag_Map` is back on, with a comment at the flag recording why.

## 3. What is actually in the tree now

Five files, +86 lines. All DC-guarded except where noted.

1. **`overhead_map.cpp` — `OGL_ResetMapFonts()` returns early when `IsStarting`.**
   The map's five atlases are no longer built at `OGL_StartRun`. Teardown still
   runs: once the map has been opened those textures exist and
   `OGL_ResetTextures()` releases them.

2. **`OverheadMap_OGL.cpp` + `FontHandler.h` — build on demand.**
   `FontSpecifier::OGL_EnsureTexture()` (`if (!OGL_Texture) OGL_Reset(true);`)
   called from `OverheadMap_OGL_Class::draw_text`, the one place map fonts render
   under GL. Only the fonts actually used get built — the title font plus the
   annotation font for the current scale, so roughly two of five rather than all
   five at every level load. Eager font VRAM: **1120 KB -> 384 KB.**

3. **`FontHandler.cpp` — upload-failure check.** `glGetError()` after the font's
   `glTexImage2D`. GLdc raises `GL_OUT_OF_MEMORY` and returns leaving
   `texture->data` NULL, and binding that hands the PVR a null pointer. This
   mattered less when every font was built at `OGL_StartRun` with room to spare;
   an on-demand build happens mid-game. On failure the texture is deleted,
   `TxtrID` zeroed and `OGL_Texture` set NULL, so `OGL_Render` skips the font and
   the cost is an annotation rather than a crash.

4. **`FontHandler.cpp` — inverted teardown, and `TxtrID` lifetime.** Not
   DC-guarded; this is an upstream bug. The test read

   ```c
   if (!IsStarting && !OGL_Texture)   // then glDeleteTextures(1,&TxtrID)
   ```

   which is the opposite of the comment directly above it. A font that *had* been
   built skipped the delete and then had `TxtrID` overwritten by `glGenTextures`,
   leaking the atlas it held; a font that had *never* been built called
   `glDeleteTextures` on a `TxtrID` that `Init()` never set. Neither showed while
   every font was built exactly once at startup; both are reachable now that
   fonts build on demand. Condition corrected, `TxtrID = 0` added to `Init()` and
   after the delete.

5. **`FontHandler.cpp` — `char Which` -> `int Which`** in the SDL glyph
   rasterisation loop. Every one of these fonts has glyphs past 127 (Monaco 5/18
   and both Couriers are 0..255, Monaco 9/12 are 0..217), so on a row starting at
   glyph 128 or above a signed char is negative and `widths_p[Which]` reads off
   the front of the array. The x-advances it produced disagreed with the texture
   coordinates built later in the same function, which have always used an `int`
   — so those glyphs were rasterised in one place and sampled from another. The
   Mac path at line 317 already used an `int`. There is a
   `if (Which >= 0 && Which < 256)` guard in the *other* loop, the one that
   cannot go negative; the bug was noticed once and guarded in the wrong place.

## 4. The GLdc mipmap bug — toolchain patched

`_glCalculateAverageTexel()` in `GL/framebuffer.c` extracted the texture format
as

```c
GLubyte format = ((pvrFormat & (1 << 27)) | (pvrFormat & (1 << 26))) >> 26;
```

The format is a **three-bit field at bits 27-29** — `ARGB1555 = 0 << 27`,
`RGB565 = 1 << 27`, `ARGB4444 = 2 << 27` (`GL/platform.h:61-63`, matching KOS's
`PVR_TXRFMT_*` in `dc/pvr.h:307-309`). **Bit 26 is not part of it** — that is
`GPU_TXRFMT_TWIDDLED` / `GPU_TXRFMT_NONTWIDDLED`. So the expression folds the
twiddle flag in as the format's low bit and never looks at bit 28. Compiled and
run, old expression against the corrected one:

| input | old | new |
|---|---|---|
| ARGB1555 twiddled | ARGB1555 | ARGB1555 |
| ARGB1555 nontwiddled | **ARGB4444** | ARGB1555 |
| RGB565 twiddled | RGB565 | RGB565 |
| RGB565 nontwiddled | **out of range** | RGB565 |
| ARGB4444 twiddled | **ARGB1555** | ARGB4444 |
| ARGB4444 nontwiddled | ARGB4444 | ARGB4444 |

Three of six wrong. The broken case that matters is **twiddled ARGB4444**, which
is what `_glGenerateMipmapTwiddled()` generates and what this port's textures are
— so mip levels were averaged as ARGB1555, taking alpha from the top bit and each
colour channel off by a bit. That is the discoloured mip chain the last three
commits on this branch were chasing.

Fixed by comparing the field itself:

```c
switch(pvrFormat & (7u << 27)) {
    case GPU_TXRFMT_RGB565:   format = RGB565;   break;
    case GPU_TXRFMT_ARGB4444: format = ARGB4444; break;
    default:                  format = ARGB1555; break;
}
```

Credit where due: Codex found this one. The diagnosis it gave was "ARGB4444 is
bit 28"; the sharper statement is that bit 26 is the twiddle flag, which is why
two of the six cases work and four do not behave as a simple missing-bit would
predict. Same fix either way.

**This is a real change to `/opt/toolchains/dc`, which the project rules
otherwise forbid.** Max authorised it explicitly in this session. What was done:

- Backups at
  `/opt/toolchains/dc/kos-ports/libGL/.claude-backup-2026-09-02/` —
  `framebuffer.c.dist.orig`, `framebuffer.c.build.orig`, `libGL.a.orig`.
- Patched **both** copies: `dist/libGL-1.1.1/GL/framebuffer.c` and
  `build/libGL-1.1.1/GL/framebuffer.c`. The cmake build is in-tree in `build/`
  (`CMAKE_HOME_DIRECTORY` points there), so `build/` is the one that compiles;
  `dist/` is patched too in case the port re-syncs.
- Rebuilt with `make GL -j8` in `build/libGL-1.1.1` — deliberately *not* the
  port's own `make install`, which could re-fetch from the upstream GitLab.
- Copied the result over `inst/lib/libGL.a`, which
  `/opt/toolchains/dc/kos-ports/lib/libGL.a` symlinks to. Size 1030744 ->
  1030448.
- Relinked the game against it: clean.

GLdc is built as **slim LTO** — `framebuffer.c.obj` has a zero-length `.text` and
carries `.gnu.debuglto_*` sections — so there is no machine code to inspect in
the object, and no way to verify the change at object level short of the final
link. Hence the compiled logic table above, which is the evidence.

The patch is committed to the repo at
`tools/patches/gldc-1.1.1-mipmap-format-field.patch` with instructions in its
header, so a clean machine can reproduce this toolchain. **A build made against
an unpatched libGL will differ from builds made here** — same class of problem as
the `KOS_CFLAGS` note in `CLAUDE.md`.

Not fixed, noticed while in there: `PAL4BPP` (`5 << 27`) is not handled by
`_glCalculateAverageTexel` at all. The paletted branch tests
`(pvrFormat & GPU_TXRFMT_PAL8BPP) == GPU_TXRFMT_PAL8BPP`, which `5 << 27` fails,
so a 4bpp paletted texture would fall through and be averaged as 16-bit. Only
matters if something asks GLdc to mipmap a PAL4 texture — which the "fonts as
4bpp paletted" idea would do.

  that, while sitting one upload early. Worth fixing before any soak test, since
  it is the instrument the soak would be read through.

## 6. Open, in the order I would take it

1. **Run it.** `tools/run-flycast.sh` on a test image; open the map, confirm
   annotations draw. This exercises the deferred build, the corrected teardown and
   the glyph-index fix together, and it is the only thing here checkable without
   hardware.
2. **Move the upload error check after the upload** (`OGL_Textures.cpp`). Three
   lines, and it is the instrument every VRAM measurement below depends on.
3. **Dedupe font atlases** by (font id, size, style), refcounted. Worth 128 KB of
   the remaining 384 KB, and no visual change — three identical Monaco 9 bold
   atlases collapse to one.
4. **Mipmapped walls, now that GLdc can build them.** The branch's last three
   commits were blocked on §4. This is the first thing that should be retried.
5. **Release map atlases when the map closes**, so the deferred 736 KB is
   transient rather than sticky-after-first-open.
6. **Right-size the PVR buffers.** Measure `pvr_get_stats().vtx_buffer_used_max`
   first; 640 KiB is GLdc's guess, not a measurement. Prototype by link-wrapping
   `pvr_init` rather than patching GLdc again.
7. **Budgeted LRU eviction**, then re-try full-resolution sprites with a 175+
   upload soak. This is the largest job on the list and the one that actually
   decides whether the sprites fit.

Items 3 and 5 are font work and independent of everything else. Item 4 is now
unblocked and cheap to test. Item 7 is where the 1630 KB comes from.
