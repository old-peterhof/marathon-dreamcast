## Sky: new concrete suspect and candidate fix

User clarified that photo scanlines are camera artifacts. Actual rectangular
boxes are anchored to the sky and travel offscreen with it when turning.
Do not use the photographed fine stripes or a normal diagonal wall boundary
as proof of the rendering fault.

Installed GLdc texture.c's packed BGRA/4444 -> twiddled path has no colour
conversion function; its general twiddle loop copies destStride bytes using
`dst[j] = src[j]` directly into VRAM. Native VRAM does not support byte writes
(https://mc.pp.se/dc/pvr.html). This is a hardware-only corruption candidate,
not yet verified against the user's console. A correct Morton layout alone
does NOT establish that the upload writes are hardware-valid.

b86 changes PackedLandscape's internal format from GL_ARGB4444_TWID_KOS to
GL_ARGB4444_KOS. GLdc's matching no-conversion path uses FASTCPY; PVR samples
linear 16-bit data. Original dimensions, every texel, packed colour precision,
RAM/VRAM sizes and all depth state are preserved. No external toolchain edit.
Build identity b86 sky-upload. Initial GL play build passed, log
`/tmp/alephone-b86-build.log`; monitored run `/tmp/alephone-b86-sky.log`.
Hardware confirmation still required. Do not describe it as fixed yet.

## Rumble — new failing regression, no driver edits this turn

Added `tools/test-rumble.c`, compiling the actual dc/dc_rumble.c scheduler with
mock Maple/time. Build with:

```
cc -std=c11 -Wall -Wextra -Werror tools/test-rumble.c -o /tmp/marathondc-test-rumble
/tmp/marathondc-test-rumble
```

It passes earlier assertions for priority, deadline-from-send, busy-stop retry,
pause and absent pack. It FAILS the final assertion at line 58: a request that
could not be queued remains pending indefinitely and is delivered one second
later. Cause: poll only expires a request when sent_generation == generation.
Fix with a separate bounded pending-expiry deadline while retaining the active
pulse deadline measured from successful queueing. Test weaker-overlapping
events, repeated charging, port/slot changes and disconnect too.

Hardware packet direction still unverified. Installed KOS example's "Basic
Thud" uses motor=1, fpow=7, bpow=0, freq=26, inc=1, cont=false. Current game uses
fpow=bpow=power, freq=32, inc=1, cont=true. A known-example packet is the next
controlled hardware test; don't just keep increasing amplitude. KOS example:
`/opt/toolchains/dc/kos/examples/dreamcast/rumble/rumble.c`, catalog around 98.

"Accepted" in the current game/VMU status means QUEUED by KOS, not a device
acknowledgement. purupuru_rumble_raw sets callback=NULL, queues the Maple frame,
and returns MAPLE_EOK. Change diagnostic wording and instrument actual response
if needed; don't infer successful physical vibration from that return code.
