## Changes made tonight

### Texture RAM and quality

`OGL_Textures.cpp`:

- `OGL_StartTextures()` on DC initializes null accounting pointers. `Setup()`
  allocates a collection's bitmap state only when that texture type uses it.
  Previously every loaded collection got four complete copies regardless of
  use; first-level eager allocation measured 488 KB. This is on-demand per
  (type, collection), not an elaborate new per-bitmap allocator.
- `OGL_StopTextures()` nulls pointers after deletion.
- Full-size native landscapes are expanded directly into ARGB4444 staging.
  The row writer uses exactly GLdc's nibble-truncation conversion, retaining
  each source texel. A 1024x512 sky needs 1 MB staging instead of 2 MB RGBA.
  `PackedLandscape` tracks this path; upload uses `GL_ARGB4444_TWID_KOS`,
  `GL_BGRA`, `GL_UNSIGNED_SHORT_4_4_4_4_REV`. GLdc twiddles on upload.
  Storage is allocated as uint32 words (half the pixel count) so existing
  buffer ownership/deletion remains valid. Substitutes/reduced paths stay RGBA.
- Removed about 90 lines of cumulative, misleading upload diagnostics. The old
  error check was BEFORE the upload and blamed unrelated GL errors on textures.
  New code drains old errors, checks AFTER raw/mipmapped/packed uploads, and
  reports dimensions, type, count, error, and free VRAM. VQ success joins this
  accounting. Periodic successful reports have `error=0000`.

`OGL_Setup.cpp` and `shell_sdl.cpp` now request resolution 0 for all types.
Shell startup clears `OGL_Flag_FlatLand`: actual full-resolution skies replace
flat fills. Wall mipmapping is retained. Crisp full-resolution VQ sprites and
HUD are inherited from the prior work. VQ is lossy compression that predates
this session; full dimensions do not imply mathematically lossless VQ.

### VRAM lifetime — latest change still awaiting runtime test

Inherited LRU evicts before `OGL_StartMain`, after `pvr_wait_ready()`, protects
the previous frame's textures, pins interface collection, uses 1 MB low-water
and 1.5 MB high-water marks. It has now successfully evicted during traversal.

Observed after eviction: 2475 KB free total, largest block only 1000 KB. A full
sky requires 1024 KB. GLdc's `alloc_malloc_and_defrag()` automatically compacts
on allocation failure. Inspect its source: it updates texture-object pointers,
but DOES NOT update VRAM addresses embedded in queued polygon headers.

Latest change makes `OGL_TextureFrameStart()` check BOTH total and contiguous
free VRAM. It waits for PVR on the slow path, evicts as needed, and explicitly
calls `glDefragmentTextureMemory_KOS()` at that frame boundary if the largest
block is under 1 MB. No GLdc toolchain modifications.

**Remaining concern:** This reserve is heuristic. Many first-use uploads in one
frame could still exceed it and invoke GLdc allocation-time defrag or OOM.
Raw upload failure is logged but not robustly propagated to drawing; inherited
`TextureState::Use` marks the ID resident before upload. GLdc's allocation
helper also asserts on exhaustion in this build. The cache is not yet a proof
that every worst-case level fits. Address with measured tests, not larger
unjustified reserves or mid-frame texture deletion. `glFinish`/`glFlush` in
this installed GLdc are empty, so they cannot provide synchronization.

### Definite correctness fixes

- `game_wad.cpp` included an obsolete three-argument declaration and call of
  `dc_vmu_save_game`, whose actual definition takes SEVEN arguments. Replaced
  the declaration with `dc_vmu.h`; call now supplies level name, tick count,
  difficulty, and `dc_vmu_take_target_slot()`. Previous code read undefined
  pointer/metadata/slot arguments. Compile succeeds, but save/load behavior
  has NOT yet been tested on this candidate.
- `fades.cpp`: C-callable `dc_fade_tint` return type corrected from C++ bool to
  int, matching the C caller. Removes a real LTO type mismatch.
- `TextStrings.cpp`: copy Pascal-string length+1 bytes, then append the C NUL,
  instead of reading length+2 bytes from a buffer that may only contain the
  Pascal string. Latest change still awaiting final build verification.

### Diagnostics

`screen_sdl.cpp`: once-per-second DEBUG log reports level, tick, health,
absolute heap top, total free VRAM, and largest contiguous VRAM block.

Latest addition `dc_memory_trace()` in `dc_compat.c` reports actual allocator
live/reusable bytes (`mallinfo`) and PVR vertex-buffer usage/peak. Gated on
DEBUG. Important: `sbrk(0)` is a high-water mark, NOT live heap usage; free
allocator blocks remain reusable. Prior notes sometimes treat it as live RAM.
Use new measurements before cutting sound buffers or PVR vertex capacity.
