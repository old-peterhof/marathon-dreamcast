## Later in the night (in progress; each item is its own commit)

- **Level load: 26 s + 14 s -> under a second.** `d0f96f2`. KOS's ISO9660
  driver serves any read that is not sector-aligned into a 32-byte-aligned
  buffer one sector per GD-ROM command; stdio's 1 KB buffer guaranteed that.
  `dc_read_file_span()` reads a collection or a sound in one aligned transfer.
  Measured: collections 25945 -> 480 ms, monster sounds 13712 -> 10 ms.
- **Screen flashes were opaque white.** Root cause is in GLdc: with no colour
  array enabled, its generic `glDrawArrays` path fills every vertex white and
  ignores `glColor*`. Only the fast path (3-float positions) and immediate mode
  honoured the current colour. Aleph One's sprites and walls use GL_DOUBLE
  positions and the fader quad uses 2-float positions, so none hit the fast
  path: fades drew white and opaque, and sprites and unsplit walls drew unlit.
  Fixed in GLdc (`attributes.c`, `_fillCurrentColourARGB`), recorded as item 4
  in `tools/patches/gldc-1.1.1-fixes.patch`, backups in
  `/opt/toolchains/dc/kos-ports/libGL/.claude-backup-2026-09-06/`. libGL
  rebuilt (needs `source /opt/toolchains/dc/kos/environ.sh` first, or kos-cc
  fails with `exec: --: invalid option`).
- **Teleport static is real static now.** `TextureManager::StaticNoise`: for
  `_static_transfer` the sprite's texture is rebuilt every frame at quarter
  resolution with noise in the opaque texels, dissolving by `transfer_data`
  the way the desktop stipple did. The PowerVR has no logic ops or stipple, so
  the flicker lives in the texels. Verified visually with the STATICTEST hook
  (every sprite static): correct silhouettes of noise.
- **glEnable/glDisable filter** in `dc_gl_compat.h`: unknown capabilities are
  dropped and named once instead of leaving GL_INVALID_VALUE in glGetError
  every frame.
- Test hooks, emulator only: `FADETEST` (a different fade each second) and
  `STATICTEST` (everything teleports) markers, staged by
  `make replay-test FADETEST=1 STATICTEST=1 REPLAY_SUFFIX=-fx`.

## Queue from Max, overnight

1. RAM/VRAM crash safety, console optimisation, load times -- ongoing above.
2. Screen flashes: colours and duration -- root cause found and fixed, see
   above; duration was never wrong (250 ms for a hit), it read as long because
   it was opaque.
3. Teleport static -- done, see above.
4. **Saving at save terminals** -- reproduced and fixed. `SAVETEST` calls
   `save_game()` from inside the game tick at tick 200, exactly where a
   pattern buffer calls it. The picker saved correctly every time (slot 1,
   214,805 -> 10,752 bytes, 22 blocks) but its screen was black on most runs,
   while the pause menu always drew. The difference is `over_game`: the pause
   menu paints a flat scrim into the overlay, but every other screen paints
   the plate with `dc_plate_to_screen()`, which copies 600 KB of rows into the
   video surface's pixel pointer -- and under GL that pointer is NULL. So the
   overlay had no background and the copy went to address zero: black in
   Flycast, and on a console a write to address zero is the crash Max saw.
   Fixed in `dc_screen.cpp` (paint the plate into the UI target when it is the
   GL overlay) and guarded in `dc_plate.cpp`. This also covers PREFERENCES and
   CONFIGURE CONTROLLER opened from the pause menu, which took the same path.
   A second, smaller fix in `dc_screen_run`: panel-only repaints are disabled
   under GL, where a full repaint costs the same upload anyway. And a third
   cause that looked like a bug and is not: Flycast shows a menu frame drawn
   after gameplay about five seconds late. `dc_pvr_trace()` proved the PowerVR
   rendered and flipped to it within two vblanks; the emulator keeps
   presenting its last rendered frame until it notices rendering has stopped.
   Noted in README "Testing aids". A console shows it at once.
5. **VMU save size.** Measured tonight: 214,805-byte save -> 10,752 bytes on
   the card, 22 blocks of 200. That is fold-against-the-level plus zlib level
   9 with a 128-byte header and no icon. Getting much below this means
   saving less (dynamic state only, not a folded copy of the level) or a
   stronger compressor than KOS's zlib; neither is a tonight job.
6. **GLdc's release-mode asserts were exit(1).** Running out of texture
   memory killed the console instead of losing a texture. Four asserts
   removed (patch item 6); a failed upload now raises GL_OUT_OF_MEMORY and the
   texture draws blank.
